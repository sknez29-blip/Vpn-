# Trojan: пинги проходят, а YouTube не открывается

## Суть проблемы

Trojan — это **прокси только для TCP**. Ни ICMP (ping), ни UDP он не передаёт.

- Если «пинги работают», значит ICMP идёт **мимо туннеля, напрямую**. Это показывает только, что есть сеть, но не то, что прокси реально пропускает трафик.
- YouTube при этом не грузится по одной из причин ниже.

---

## 1. QUIC / UDP — самая вероятная причина именно для YouTube

YouTube и остальные сервисы Google активно используют **QUIC (HTTP/3 поверх UDP, порт 443)**. Trojan UDP не пропускает. Браузер сначала пробует QUIC, пакеты пропадают, и страница **висит**, а не переключается на обычный TCP.

**Что сделать (от простого к сложному):**

- Отключить QUIC в браузере:
  - Chrome: `chrome://flags` → `Experimental QUIC protocol` → **Disabled**
  - Firefox: `about:config` → `network.http.http3.enable` → **false**
- Или на сервере/роутере закрыть UDP 443 через REJECT, чтобы браузер сразу ушёл на TCP:
  ```bash
  iptables -A FORWARD -p udp --dport 443 -j REJECT
  ```
- Или перейти на клиент/протокол, который умеет UDP (sing-box, Xray с UDP over TCP, Hysteria2, TUIC). У «чистого» Trojan такой поддержки нет.

---

## 2. MTU / MSS — вторая по частоте причина

Маленькие пакеты (ping, DNS) проходят, а большие (TLS-рукопожатие, видео) **молча отбрасываются**, потому что не влезают в MTU, а флаг DF запрещает их дробить. Типичная картина: «пингуется, но сайты не грузятся или грузятся наполовину».

**Как найти рабочий MTU:**
```bash
ping -M do -s 1400 8.8.8.8
```
Если пакеты теряются, уменьшайте размер (1380, 1360…). Рабочий размер + 28 = ваш MTU.

**Как исправить:** включить клампинг MSS на сервере:
```bash
iptables -t mangle -A FORWARD -p tcp --syn -j TCPMSS --clamp-mss-to-pmtu
```

---

## 3. DNS

Если имена не резолвятся через туннель, обычно **не работает вообще всё**, а не один YouTube. Проверка:
```bash
nslookup youtube.com
```

---

## Как быстро найти причину

На клиенте при включённом Trojan:
```bash
curl -v https://www.youtube.com   # TCP через прокси: должен ответить
curl -v https://ident.me          # какой IP видит внешний сайт
```

| Результат | Причина |
|---|---|
| `curl` до YouTube проходит, а браузер нет | **QUIC** (пункт 1) |
| `curl` висит или рвётся на рукопожатии | **MTU/MSS** (пункт 2) |
| `ident.me` показывает домашний IP, а не IP сервера | трафик не идёт через прокси: **ошибка маршрутизации/правил** |

**С чего начать:** отключите QUIC в браузере. Когда «не работает только YouTube», чаще всего помогает именно это.

---

## Безопасность

- Не пересылайте логин и пароль от сервера в открытом виде. Если они уже где-то засветились, смените пароль.
- Лучше заходить по SSH-ключу, а вход по паролю отключить (`PasswordAuthentication no` в `/etc/ssh/sshd_config`).
